# ALS and Parkinson's Clinical Trials Dashboard

A dashboard for tracking clinical trials in amyotrophic lateral sclerosis (ALS) and Parkinson's disease. A switch at the top chooses the disease; the ALS dashboard is the landing page and `#parkinsons` opens Parkinson's. Views:

- **All registered studies** — a searchable, filterable catalog of every study of the disease registered on ClinicalTrials.gov, plus trials found only in the UK and EU registries (about 1,100 for ALS and 5,000 for Parkinson's: interventional trials, observational studies and expanded-access programs). Tap **Follow** on a study to pin it to the top; followed studies are saved in that browser only (`localStorage`), since the site has no accounts.
- **Featured trials** (`#featured`, ALS only) — notable late-stage trials with hand-researched summaries: therapy/modality background, preclinical evidence, phase and design, results reported so far, and estimated timeframes for future readouts.

## Data model

- `public/data/<disease>-registry.json` (`als`, `pd`) — one registry catalog per disease, generated by `npm run fetch-registry -- <disease>` (`scripts/fetch-registry.mjs`). Each disease's settings are in `scripts/diseases.mjs`: its ClinicalTrials.gov condition searches and the words a result must contain (for ALS, every study from the ALS search that names ALS or motor neuron disease, plus ALS studies indexed only under "motor neuron disease"; for Parkinson's, the Parkinson disease search, keeping studies that name Parkinson's), its other-registry queries, its focus rules and its background drug. Its hand-curated files are in `scripts/data/<disease>/`: `outcomes.json`, `focus.json`, `duplicates.json` and the saved EU register copy `euctr.json`. The app loads a disease's catalog only when it is opened, and the installed app caches each one on first use. The deploy workflow regenerates both catalogs on every deploy and falls back to a disease's committed snapshot if its refresh fails. Coverage limits: few trials before about 2000 were registered, and trials registered only in other countries' registries are not included.
- `scripts/other-registries.mjs` — each disease's trials registered outside ClinicalTrials.gov: the UK's ISRCTN registry (public API), the EU's CTIS (public search API, trials authorised from 2023) and the older EU Clinical Trials Register (EudraCT). Each record is reshaped into ClinicalTrials.gov's form so drug matching, focus, outcomes and furthest phase work the same, and keeps a link to its own registry. Trials already in the catalog are dropped by their cross-referenced numbers (NCT, EudraCT, CTIS, ISRCTN, including EudraCT numbers carried over to CTIS); records with no cross-reference count as duplicates when a ClinicalTrials.gov trial in a shared country tests the same recognised drug at a shared phase and started within a year, or has a near-identical title (trials with a Phase 1 part need similar titles; platform trials are never matched by drug). `scripts/data/<disease>/duplicates.json` lists, by hand, duplicates those rules can't catch safely. ISRCTN and CTIS are fetched on every build, falling back to the previous snapshot's records if unreachable. The EU Clinical Trials Register closed to new trials and its firewall rejects repeated bulk downloads, so the build reads a saved copy, `scripts/data/<disease>/euctr.json`, refreshed by hand with `npm run fetch-euctr -- <disease>` (slow on purpose, and it stops at the first rejection). Parkinson's has no saved copy yet: the register cut the connection when it was first downloaded. WHO ICTRP, which would add Japan, China, Australia and others, has no free programmatic access, so those registries aren't covered yet.
- `scripts/drugs.json` — the drug table: for each drug, the names and company codes it is matched by, other names (e.g. ION363 = ulefnersen), its **target(s)** and **modality**, and a source. Entries for company codes cite the public source that identifies the code; entries for well-characterised drugs cite ChEMBL or another checked source where one was available, and otherwise state standard, widely documented pharmacology (`source: null`). The fetch script matches each study's interventions against it (specific products before generic ingredients), so the catalog can be searched and filtered by target and modality. Drugs it doesn't cover show as "Not yet classified"; add an entry only when the target is established. The table is shared by both diseases (a drug's target doesn't depend on the disease); `approvals` notes, per disease, a drug approved for it. The Parkinson's entries were added from ChEMBL lookups (compound, mechanism and target) for established drugs, and from the trial record or a press or journal report for company codes; codes whose mechanism couldn't be confirmed are left out. Drugs given only as probes in drug-interaction or QT studies (midazolam, caffeine and similar) are ignored when the study tests another drug.
- **Furthest phase in the disease:** for every trial before Phase 3, the fetch script finds the furthest phase any trial of the same drug in the same disease reached (matching code names and drug names through `scripts/drugs.json`), ignoring withdrawn trials and Phase 4 studies, and preferring the drug's own main trial over extensions and platform master protocols. Drug-table entries marked `group: true` (classes such as mesenchymal stem cells or corticosteroids) are matched by each study's own product name instead, so different products aren't treated as one drug. It only sees ClinicalTrials.gov: a drug that moved on in another country's registry, or to another disease, shows as not advanced.
- **Dose details:** `scripts/dosing.mjs` reads each recognised drug's dose levels, frequency and route from the registry's free text: intervention descriptions and the descriptions of the arms that give the drug (placebo arms are skipped). A dose or route mentioned right after another drug's name, or after "placebo", goes to that one, so a background drug's dose isn't credited to the drug under test. CTIS records give route, form and maximum daily dose as fields, which the CTIS reader writes into the description. The registry passages it read are kept, and the catalog shows them under the summary in each drug's "Dose details" dropdown, since pattern matching can misread unusual wording. The saved copy of the EU Clinical Trials Register doesn't include its dose fields, so those trials have no dose details yet.
- **Development timeline:** every study that tests a recognised drug has a "Development timeline" link. It opens a panel listing every trial of that drug in the same disease, in any covered registry, by start date, with phase, status and outcome; each one expands to its full catalog entry. A phase ladder shows how far the drug got, and the timeline ends in one of these states: approved (or approved then withdrawn), still in trials, no next trial yet (the last one ended within two years), or stopped, giving the phase it stopped at and the result of the trial that decided it. Approvals come from the `approvals` field in `scripts/drugs.json`, set by hand per disease for approved drugs. Each study's drugs are stored as `drugKeys`, which link the trials of one drug. Platform master protocols appear on the timeline, but the end state is judged from the drug's own trials. A platform record that registers a single drug, such as a HEALEY regimen, counts as one of the drug's own trials. "Stopped" only means no trial in that disease has been registered since; the drug may still be in development elsewhere or in another disease.
- **Focus:** the fetch script also sorts every study by what it is mainly for — slowing the disease, symptom management (e.g. pseudobulbar affect, drooling, cramps in ALS; motor fluctuations, dyskinesia, psychosis or constipation in Parkinson's), supportive care (breathing support, nutrition, rehabilitation, exercise, communication devices), diagnostics and biomarkers, natural history and other research, or other-disease studies where the disease is one of several conditions. It decides from the registry record (primary purpose, title, conditions, intervention types), and `scripts/data/<disease>/focus.json` holds hand corrections where those rules get it wrong. The catalog opens on slowing the disease. Parkinson's has established symptomatic drug classes, so it has three more rules: a drug trial whose recognised drugs all belong to those classes (dopaminergic drugs, COMT and MAO-B inhibitors, A2A antagonists, antidepressants, sleep and gut drugs and so on) counts as symptom management unless its title speaks of progression or disease modification; brain stimulation and surgery count as symptom management; and other non-drug studies count as supportive care or research. Its default focus is "Slowing or reversing Parkinson's", which includes cell and gene therapies that aim to restore dopamine neurons.
- `scripts/data/<disease>/outcomes.json` — hand-researched outcomes for finished studies (met or missed the primary endpoint, stopped for futility or safety, extension study, and so on), each with a plain-language summary and a source. The fetch script attaches them to the catalog; other interventional studies get an automatic outcome from the registry record instead: its stop reason sorted into a few kinds (no benefit, safety, slow enrollment, business or funding), whether results are posted, and publications the registry links as results. For ALS the late-stage (Phase 2/3 and 3) trials are researched; for Parkinson's, so far the major finished disease-modifying trials (Phase 2 and 3, each checked against its results paper in PubMed); add entries as more are.
- `src/data/targets.ts` — groups every target into one of ten pathways (genetic targets; nerve excitability and glutamate; inflammation and immunity; protein handling and stress responses; mitochondria and energy metabolism; oxidative stress; axons, synapses and muscle; growth factors and cell therapy; neurotransmitter and hormone receptors; other), so the target filter can be browsed and filtered by pathway, and marks labels that describe a broad process or cell type rather than a molecule ("Mitochondrial and energy metabolism", "Oxidative stress", "Regulatory T cells") as mechanisms, shown as "Mechanism" instead of "Target". New target labels in `scripts/drugs.json` should reuse an existing label where one fits, and be added to a pathway here (anything unassigned shows under "Other"). It also holds other names for each target (e.g. ATXN2 = ataxin-2, SOD1 = superoxide dismutase 1), so searching any of them finds the same studies. Use the target names it lists when adding drugs, so the target filter doesn't split one target into two. The search itself (`src/lib/search.ts`) ignores case, hyphens and spaces ("TDP-43" = "tdp43"), and matches terms of three characters or fewer only at the start of a word, so "FUS" doesn't match "infusion".
- `src/data/trials.ts` — hand-curated snapshot of notable ongoing trials plus readouts from the past three years, researched from public sources (ClinicalTrials.gov, sponsor press releases, peer-reviewed literature). Each entry cites its sources.
- `src/lib/clinicalTrialsApi.ts` + `useLiveTrialStatuses` — on load (and on demand via "Refresh live status"), the app queries the public [ClinicalTrials.gov API v2](https://clinicaltrials.gov/data-api/api) client-side for each trial's NCT ID and overlays live `overallStatus`, `enrollmentCount`, and `primaryCompletionDate` onto the curated card/detail view. If that request fails (offline, network policy, API changes) the UI falls back to the curated snapshot silently — there is always something reasonable to show.

## Running locally

```bash
npm install
npm run dev      # start dev server
npm run build    # type-check + production build
npm run preview  # preview the production build
npm run fetch-registry -- als  # regenerate a disease's registry catalog: als or pd (behind an HTTPS proxy on Node 22+, prefix with NODE_USE_ENV_PROXY=1)
npm run fetch-euctr -- als     # refresh a disease's saved EU Clinical Trials Register copy (occasionally; slow)
```

## Updating the dataset

Edit `src/data/trials.ts` directly — add a new `Trial` entry (see `src/types/trial.ts` for the shape) or update an existing one's `results` array as new readouts are published. Keep `dataAsOf` current when you do a research pass.
