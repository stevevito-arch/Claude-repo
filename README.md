# ALS Clinical Trials Dashboard

A dashboard for tracking amyotrophic lateral sclerosis (ALS) clinical trials. It has two views:

- **All registered studies** (the landing page) — a searchable, filterable catalog of every ALS study registered on ClinicalTrials.gov (about 1,000 studies: interventional trials, observational studies and expanded-access programs). Tap **Follow** on a study to pin it to the top; followed studies are saved in that browser only (`localStorage`), since the site has no accounts.
- **Featured trials** (`#featured`) — notable late-stage trials with hand-researched summaries: therapy/modality background, preclinical evidence, phase and design, results reported so far, and estimated timeframes for future readouts.

## Data model

- `public/data/als-registry.json` — the registry catalog, generated by `npm run fetch-registry` (`scripts/fetch-registry.mjs`). It takes every study from the registry's ALS condition search, keeps only those whose record names ALS or motor neuron disease, and adds ALS studies indexed only under "motor neuron disease". The deploy workflow regenerates it on every deploy and falls back to the committed snapshot if the API is unreachable. Coverage limits: few trials before about 2000 were registered, and trials registered only in other countries' registries are not included.
- `scripts/other-registries.mjs` — ALS trials registered outside ClinicalTrials.gov: the UK's ISRCTN registry (public API), the EU's CTIS (public search API, trials authorised from 2023) and the older EU Clinical Trials Register (EudraCT). Each record is reshaped into ClinicalTrials.gov's form so drug matching, focus, outcomes and furthest phase work the same, and keeps a link to its own registry. Trials already in the catalog are dropped by their cross-referenced numbers (NCT, EudraCT, CTIS, ISRCTN, including EudraCT numbers carried over to CTIS); records with no cross-reference count as duplicates when a ClinicalTrials.gov trial in a shared country tests the same recognised drug at a shared phase and started within a year, or has a near-identical title (trials with a Phase 1 part need similar titles; platform trials are never matched by drug). `scripts/duplicates.json` lists, by hand, duplicates those rules can't catch safely. ISRCTN and CTIS are fetched on every build, falling back to the previous snapshot's records if unreachable. The EU Clinical Trials Register closed to new trials and its firewall rejects repeated bulk downloads, so the build reads a saved copy, `scripts/euctr-als.json`, refreshed by hand with `npm run fetch-euctr` (slow on purpose, and it stops at the first rejection). WHO ICTRP, which would add Japan, China, Australia and others, has no free programmatic access, so those registries aren't covered yet.
- `scripts/drugs.json` — the drug table: for each drug, the names and company codes it is matched by, other names (e.g. ION363 = ulefnersen), its **target(s)** and **modality**, and a source. Entries for company codes cite the public source that identifies the code; entries for well-characterised drugs cite ChEMBL or another checked source where one was available, and otherwise state standard, widely documented pharmacology (`source: null`). The fetch script matches each study's interventions against it (specific products before generic ingredients), so the catalog can be searched and filtered by target and modality. Drugs it doesn't cover show as "Not yet classified"; add an entry only when the target is established.
- **Furthest phase in ALS:** for every trial before Phase 3, the fetch script finds the furthest phase any ALS trial of the same drug reached (matching code names and drug names through `scripts/drugs.json`), ignoring withdrawn trials and Phase 4 studies, and preferring the drug's own main trial over extensions and platform master protocols. Drug-table entries marked `group: true` (classes such as mesenchymal stem cells or corticosteroids) are matched by each study's own product name instead, so different products aren't treated as one drug. It only sees ClinicalTrials.gov: a drug that moved on in another country's registry, or to another disease, shows as not advanced.
- **Focus:** the fetch script also sorts every study by what it is mainly for — slowing ALS progression, symptom management (e.g. pseudobulbar affect, drooling, cramps), supportive care (breathing support, nutrition, rehabilitation, communication devices), diagnostics and biomarkers, natural history and other research, or other-disease studies where ALS is one of several conditions. It decides from the registry record (primary purpose, title, conditions, intervention types), and `scripts/focus.json` holds hand corrections where those rules get it wrong. The catalog opens on slowing ALS progression.
- `scripts/outcomes.json` — hand-researched outcomes for finished studies (met or missed the primary endpoint, stopped for futility or safety, extension study, and so on), each with a plain-language summary and a source. The fetch script attaches them to the catalog; other interventional studies get an automatic outcome from the registry record instead: its stop reason sorted into a few kinds (no benefit, safety, slow enrollment, business or funding), whether results are posted, and publications the registry links as results. So far the late-stage (Phase 2/3 and 3) trials are researched; add entries as more are.
- `src/data/targets.ts` — groups every target into one of ten pathways (genetic targets; nerve excitability and glutamate; inflammation and immunity; protein handling and stress responses; mitochondria and energy metabolism; oxidative stress; axons, synapses and muscle; growth factors and cell therapy; neurotransmitter and hormone receptors; other), so the target filter can be browsed and filtered by pathway, and marks labels that describe a broad process or cell type rather than a molecule ("Mitochondrial and energy metabolism", "Oxidative stress", "Regulatory T cells") as mechanisms, shown as "Mechanism" instead of "Target". New target labels in `scripts/drugs.json` should reuse an existing label where one fits, and be added to a pathway here (anything unassigned shows under "Other"). It also holds other names for each target (e.g. ATXN2 = ataxin-2, SOD1 = superoxide dismutase 1), so searching any of them finds the same studies. Use the target names it lists when adding drugs, so the target filter doesn't split one target into two. The search itself (`src/lib/search.ts`) ignores case, hyphens and spaces ("TDP-43" = "tdp43"), and matches terms of three characters or fewer only at the start of a word, so "FUS" doesn't match "infusion".
- `src/data/trials.ts` — hand-curated snapshot of notable ongoing trials plus readouts from the past three years, researched from public sources (ClinicalTrials.gov, sponsor press releases, peer-reviewed literature). Each entry cites its sources.
- `src/lib/clinicalTrialsApi.ts` + `useLiveTrialStatuses` — on load (and on demand via "Refresh live status"), the app queries the public [ClinicalTrials.gov API v2](https://clinicaltrials.gov/data-api/api) client-side for each trial's NCT ID and overlays live `overallStatus`, `enrollmentCount`, and `primaryCompletionDate` onto the curated card/detail view. If that request fails (offline, network policy, API changes) the UI falls back to the curated snapshot silently — there is always something reasonable to show.

## Running locally

```bash
npm install
npm run dev      # start dev server
npm run build    # type-check + production build
npm run preview  # preview the production build
npm run fetch-registry  # regenerate the registry catalog (behind an HTTPS proxy on Node 22+, prefix with NODE_USE_ENV_PROXY=1)
npm run fetch-euctr     # refresh the saved EU Clinical Trials Register copy (occasionally; slow)
```

## Updating the dataset

Edit `src/data/trials.ts` directly — add a new `Trial` entry (see `src/types/trial.ts` for the shape) or update an existing one's `results` array as new readouts are published. Keep `dataAsOf` current when you do a research pass.
